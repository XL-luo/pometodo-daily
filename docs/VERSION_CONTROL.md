## 新需求怎么开始

从 Obsidian 的 timToDo 项目或源码目录开启聊天，直接描述需求即可。两处 `AGENTS.md` 都指向源码开发规则。恢复旧聊天也要先重新读取规则。任意其他目录打开的聊天需显式提供 `D:\PomeTodo-Source\AGENTS.md`。

多个聊天可以讨论需求；写代码前必须使用 `scripts/dev-session.ps1` 申请占用。脚本支持 `status`、`acquire -Owner <聊天ID> -Task <摘要>`、`release -Owner <聊天ID>`。工作记录位于 `.git/codex-dev-session.json`，互斥句柄位于 `.git/codex-dev-session.guard`；guard 文件残留不代表仍占用。

在只读 Git 元数据的执行沙箱中，申请/释放占用与提交需要获得执行权限，不能因此跳过。失败时停止写代码并如实交接。不得根据时间自动清除占用；核对原聊天停止、遗留改动与交接信息后再释放旧 owner。

正常交付顺序为：验证 → 更新日志 → 审阅并提交明确文件 → 确认远程身份与预期可见性并推送 → 同步当前进度 → 释放占用。该流程是助手必须执行的规则，不是后台自动提交服务。
